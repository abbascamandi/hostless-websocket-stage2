# Aether + Xray on Hostless — Stage 3

This stage combines the Aether WARP client, Xray-core and a small HTTP/WebSocket
front gateway in **one Docker container**. Keeping them in one container is
intentional: Xray sends traffic to Aether's SOCKS5 listener over `127.0.0.1`.

The public side is a VLESS inbound transported by WebSocket. Hostless terminates
public HTTPS/TLS and forwards the HTTP/WebSocket request to this app. Xray's
WebSocket inbound listens only on `127.0.0.1:10000`; the Aether SOCKS5 endpoint
listens only on `127.0.0.1:1819`. Neither internal port is exposed publicly.

## Before deploying

1. Stop/pause the Stage 1 standalone Worker while testing this combined App, so
   it does not consume the free plan's shared CPU/RAM allowance.
2. Keep the Stage 2 App and its public Hostless hostname; this repository can
   replace the Stage 2 WebSocket echo-test code.
3. Attach a persistent Hostless disk to this App at the exact mount path `/data`.
   A 1 GiB disk is sufficient for the Aether identity/config files. Check the
   price shown by Hostless before creating/attaching it.
4. Keep one App replica. The container intentionally refuses to start if `/data`
   is not mounted, preventing accidental creation of a new WARP identity on each
   redeploy.

## Files

- `Dockerfile`: combines the known-working Aether binary with official Xray-core
  `26.11.9` and Node.js.
- `start.sh`: starts the HTTP gateway, starts Aether, verifies `warp=on`, validates
  and starts Xray, then marks the service ready.
- `server.js`: answers `/healthz` and `/readyz`, and forwards only the configured
  WebSocket path to Xray without modifying the VLESS stream.
- `generate-config.js`: creates the Xray config from Hostless environment variables.
- `wait-port.js`: waits for Xray's localhost listener before declaring readiness.
- `hostless.yaml`: configures the HTTP health check.

## Hostless App settings

- Build system: **Docker**
- Dockerfile path: `./Dockerfile`
- Start command: `/usr/local/bin/start.sh`
- Replicas: `1`
- Health check: HTTP `GET /healthz` (also declared in `hostless.yaml`)
- Storage: persistent disk mounted at `/data`
- Do not set/override Hostless's `PORT`; it is provided by Hostless.

If the app was created in Stage 2, update its Git repository to these files and
change the old `npm start` override to `/usr/local/bin/start.sh`.

## Required Hostless environment variables

Create these two secrets under App → Settings → Environment variables:

- `VLESS_UUID`: a UUID generated by you, e.g. with PowerShell:
  `[guid]::NewGuid().ToString()`
- `WS_PATH`: a private path beginning with `/`, generated by PowerShell:
  `"/" + [guid]::NewGuid().ToString("N")`

Use your own generated values. Do not commit them to GitHub, put them in source
files, or paste them into public chats/screenshots. Do not reuse the Stage 2
`WS_TEST_TOKEN`; remove that old variable.

The app sets these defaults internally:

- Aether SOCKS5: `127.0.0.1:1819`
- Aether persistent config: `/data/aether.toml`
- Aether MASQUE config: `/data/aether-masque.toml`
- Xray internal listener: `127.0.0.1:10000`
- Xray outbound: SOCKS5 `127.0.0.1:1819`

## Expected startup logs

The useful lines are similar to:

```text
[stage-3] SUCCESS: Aether data path verified (warp=on).
[config] Xray VLESS/WebSocket config generated. Credentials are not printed.
Configuration OK.
[startup] Xray is listening on 127.0.0.1:10000.
[stage-3] READY: VLESS over WebSocket is available through the Hostless App HTTPS endpoint.
```

The exact Xray startup wording can vary by release. The final `[stage-3] READY`
line and a successful `https://YOUR-APP-HOST/readyz` response are the readiness
indicators.

## VLESS client parameters (after deployment is ready)

Use these in a VLESS client such as v2rayNG or Hiddify:

- Address: the Hostless App hostname (without `https://`)
- Port: `443`
- UUID: the `VLESS_UUID` secret you generated
- Encryption: `none`
- Network/Transport: `WebSocket (ws)`
- WebSocket path: the exact `WS_PATH` secret you generated
- TLS: enabled
- SNI: the Hostless App hostname
- Host header: the Hostless App hostname
- ALPN: leave automatic/default initially

The client URI shape is:

```text
vless://UUID@APP-HOST:443?encryption=none&security=tls&sni=APP-HOST&type=ws&host=APP-HOST&path=%2FYOUR-WS-PATH#Aether-WARP
```

Replace the placeholders locally. Do not share the resulting URI: it contains
working credentials.

## Endpoints

- `GET /healthz`: liveness check for Hostless (200 while the Node gateway is running).
- `GET /readyz`: returns 200 only after Aether and Xray are ready; otherwise 503.
- WebSocket: only the configured `WS_PATH` is forwarded to Xray.

## Important test scope

First verify a VLESS connection and ordinary TCP/HTTPS browsing. UDP-dependent
applications and DNS behavior should be tested separately; do not assume they
work just because a TCP website loads.
